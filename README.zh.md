# dsh-handoff-log

DeepSeek Harness 插件包，加载 **handoff-log** 技能：在项目目录里维护一份交接记录，任何 agent 或人随时能接手。

## 它做什么

技能在项目根目录维护两个文件：

- **`AGENTS.md`** — 门牌。几乎所有 coding agent 都会自动读取它，它指向交接本。
- **`HANDOFF.md`** — 交接本，四节：目标与走向、当前进度、下一步、只追加不删改的踩坑记录与解法。

记录落在项目目录而不是某个 agent 的记忆里，所以换会话、换模型、换工具都能接上。

## 什么时候触发

开工时让 agent 初始化交接日志；接手时先读并核验它；每次工作结束前更新它。说到「交接」「项目日志」「记录进度」「踩坑记录」「多个 agent 做同一个项目」时也会加载。

覆盖三种场景：

1. **初始化** — 用包内模板生成 `AGENTS.md` 和 `HANDOFF.md`。
2. **接手** — 读门牌、读交接本，然后**核验**记录的进度，而不是直接相信上一手写的「已完成」。
3. **交班** — 写可验证的进度、可执行的下一步，每个已解决的坑追加一条记录。

并行协作也有约定：同一时间只有一个写者，动工前登记占用行。

## 它守的规则

- 接手先读，交班必写。
- 只追加不删改。过时的内容标注「已被 X 取代」，不抹掉。
- 项目级的坑留在项目里；环境级的备忘进全局档案。
- 密钥、token、私人配置永不写进交接记录——只写去哪里取。

## 安装

DSH 里打开 **插件** → **添加插件**，填包目录、npm 包名或仓库地址均可。

命令行同样可以装：

```
dsh plugin add /absolute/path/to/dsh-handoff-log
```

## 关掉会怎样

技能从 agent 目录里消失。项目目录里已经生成的文件保持原样。
