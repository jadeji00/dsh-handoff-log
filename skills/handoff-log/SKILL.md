# handoff-log：项目交接日志

## 为什么

agent 的记忆会断，文件不会。项目目录里的 `AGENTS.md` 会被几乎所有 coding agent 自动读取，它指向的 `HANDOFF.md` 就是项目的"活档案"：任何 agent 或人打开项目目录就能接手，不需要口头交接。

这个体系只有两条铁律：

1. **接手先读，交班必写。** 不读就动手会重复踩坑；不写就走等于这次工作对下一个人不可见。
2. **只追加，不删改。** 坑的历史是最值钱的资产，删了就没了。过时的内容用"已被 X 取代（日期）"标注，而不是抹掉。

## 三种场景

### A. 新项目初始化

在项目根目录创建两个文件（模板见 `scripts/` 目录，可直接复制）：

- `AGENTS.md` — 门牌：指向 HANDOFF.md + 读写规则 + 项目硬约束（端口分配、不能动的文件、技术栈约定等）
- `HANDOFF.md` — 交接本：目标走向 / 当前进度 / 下一步 / 踩坑记录 四节

`AGENTS.md` 顶部必须有一句明确的指向（这是其他 agent 能找到交接本的唯一线索）：

```markdown
> **接手本项目前必读 `HANDOFF.md`**；结束工作时必须更新它（进度、坑、下一步）。
```

初始化时问用户拿三样东西填进去：项目一句话目标、整体思路走向（3-5 条）、已知硬约束。填不全就留 `（待补）`，别编造。

### B. 接手已有项目（含本体系的）

动手前：

1. 读 `AGENTS.md`（没有它但存在 `HANDOFF.md` 时，提醒用户补一个门牌）
2. 读 `HANDOFF.md` 全文
3. **核验「当前进度」**：上一手写的"已完成"要按可验证的方式确认（跑一下、看文件、查端口），别直接采信。发现与实际不符，先修正交接本再动手，并在坑里记一笔"交接状态失真"。

### C2. 并行协作（多个 agent 同时做同一项目）

交接本只有一个，同时写会互相覆盖。约定：

- **同一时间原则上只有一手在写交接本。** 动工前先读抬头确认没有别人正在干；如果要并行，在「当前进度」里先登记一行占用：`YYYY-MM-DD HH:MM <署名> 开始处理：<范围>`，做完交班时随更新一起清掉。
- **修改同一份文件前先看交接本里有没有别人认领了同一块**，撞了就换范围或先沟通，别互相覆盖。
- 并行的各手交班时**只改自己负责的小节行，不动别人的记录**；抬头日期取最新一手。

### C. 交班（每次工作结束前）

更新 `HANDOFF.md`：

1. 抬头：日期 + 署名（哪个 agent / 哪个人）
2. 「当前进度」：已完成的写**可验证状态**（"X 接口返回 200"而非"X 做好了"）；进行中的写清卡在哪
3. 「下一步」：写成下一个人照着就能动的具体动作，不要写"继续优化"这种无法执行的
4. 「踩坑记录」：本次遇到并已解决的坑，追加一条：`日期 [坑] 症状 → 根因 → 解法 (署名)`

只追加不删除；如果某条坑后来被证伪或有了更好解法，在原条末尾追加"→ 更新（日期）：…"，不改原文。

## 分层原则

- **项目级**的坑（只在这个项目发生）→ 留在 `HANDOFF.md`
- **环境级**的坑（所有项目都会踩：PATH、镜像源、系统服务）→ 提醒用户考虑写进全局档案（如 profile / project-map 类文件），别混进项目日志
- **会话级**的上下文（这次对话的详细推理）→ 不属于交接本，交接本只留结论
- **安全红线**：密钥、token、私人配置**永不写进** `HANDOFF.md` 或 `AGENTS.md`——交接本会被每个接手的 agent 和人读到，还可能被同步、提交进 git。交接时只能写"配置在 X 处，去那里取"，不能写配置本身。（OpenMausBot 的多 bot 同步就把 agent 配置文件与密钥目录列入"永不离开本机"清单，同理。）

## 规模升级（可选）

默认两文件版覆盖大多数项目。只有当项目明显变大（多模块、多角色、长周期）时，才考虑升级为 `AI_DOC/PROJECT_CONTEXT.md + AI_memory/` 的完整结构（结构解剖 / 当前态 / 技术契约 / 编年史四块）。升级前先问用户——维护成本高的体系坚持不下去，宁可小而活，不可大而死。

## 模板文件

`scripts/` 目录下有两个可直接复制的模板：

- `AGENTS.template.md` → 复制为项目根的 `AGENTS.md`
- `HANDOFF.template.md` → 复制为项目根的 `HANDOFF.md`

复制后把 `{{占位}}` 填掉，没信息的留 `（待补）`。
